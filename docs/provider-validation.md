# Проверка источников и основы реализации

Дата проверки: 2026-11-17. Машина: Windows 11 26200, x64, Python 3.14.8.
Все проверки ниже выполнены реальными запросами с этого ПК; секреты не использовались.

## Итог

Выбрана разработка с нуля на Python 3.14 + PySide6 6.12 (Qt Widgets, QMediaPlayer),
источник — **Audius** (`https://api.audius.co/v1`). Audius — открытый музыкальный
каталог с публичным REST API, который не требует ключа, аккаунта и подписки для
поиска и стриминга; документация прямо описывает API как открытый и предназначенный
для приложений, которые ищут и воспроизводят музыку.

Причины: реальный полнотрековый поток проверен, каталог доступен без регистрации,
нет встроенного браузера/DRM, значит PySide6 + QMediaPlayer укладывается в бюджет
процессов лучше Electron-вариантов. Ограничения Audius (каталог независимых
артистов, а не топ-чарты мейджоров) честно указаны в интерфейсе и отчёте.

## Что проверено фактически

### Audius — подходит

1. **Поиск.** `GET https://discoveryprovider.audius.co/v1/tracks/search?query=daft%20punk&app_name=MyMusic&limit=3`
   → HTTP 200, JSON с реальными треками (id, title, user.name, duration, artwork).
2. **Пагинация.** Тот же запрос с `offset=5` вернул другие 5 треков → серверная
   постраничная выдача работает.
3. **Метаданные трека.** `GET /v1/tracks/{id}` → поля `is_streamable`, `duration`
   (секунды), `artwork['480x480']`, `permalink`, `license`, `user`.
4. **Полный поток.** `GET /v1/tracks/vZJJz/stream?app_name=MyMusic` с `Range: bytes=0-200000`
   → HTTP 206, `audio/mpeg`, 200 001 байт, файл распознан как MP3 320 kbps 48 kHz
   stereo. Redirect ведёт на подписанный HTTPS URL (Cloudflare R2), срок действия
   подписи ~2 часа. Это полнотрековый поток, а не превью.
5. **Условия.** Официальная документация Audius: https://docs.audius.org/developers/api/
   и https://audius.co/agents.md — API позиционируется как открытое, «permissionless»
   для стриминга; для базовых запросов ключ не нужен, `app_name` обязателен.
   Ключи/планы (https://api.audius.co/plans) относятся к повышенным лимитам и для
   первой версии не требуются.
6. **Заголовки.** Ответы API по HTTPS, HSTS; `Retry-After` при 429 обрабатывается
   клиентом. Токенов/аккаунта нет — хранить секреты не требуется.

Ограничения, принятые явно:
- Каталог Audius — независимые и загруженные артисты, не гарантирует популярные
  мейджор-релизы. Это свойство источника, а не обход ограничений.
- Подписанные URL краткоживущие: URL не сохраняется на диск, при истечении
  выполняется повторное разрешение того же трека.
- Требуется сеть; офлайн-режим не обещается.

### Jamendo — не подходит без решения пользователя

`GET https://api.jamendo.com/v3.0/tracks/?client_id=test` → HTTP 200,
`"error_message": "Jamendo Api Invalid Client Id Error: Your credential is not authorized."`.
Нужен client_id (регистрация приложения), то есть решение D06. Не использован.

### Internet Archive — не проверено

`GET https://archive.org/advancedsearch.php?...` дважды завершился HTTP 000
(тайм-аут соединения с этой машины). Условия и поток не подтверждены, поэтому
источником не выбран; повторная проверка возможна при желании пользователя.

### YouTube / Spotify — по-прежнему не подходят

См. docs/03: скрытое аудио YouTube запрещено политикой API; Spotify Web Playback SDK
требует Premium, браузерную среду и DRM. Оба варианта меняют продукт или требуют
решений пользователя (D05/D06) и не использованы.

## Готовые основы

- **Nuclear** (Electron/React) — функциональный агрегатор, но добавляет Chromium и
  несколько процессов; виджет и заявленный фон не подтверждены; лицензия и плагины
  требуют отдельной проверки. Для приоритета «минимальное влияние на процессы»
  проигрывает нативному Qt-клиенту.
- **Spotube** (Flutter) — источник Spotify/YouTube, то есть те же ограничения
  провайдеров; нативная сборка Windows не проверена.
- **muffon** (Electron) — те же накладные расходы браузерных процессов, источник
  Last.fm/Discogs и стриминг-сервисы с ограничениями.
- **Navidrome** — сервер личной коллекции, не решает поиск интернет-каталога.

Ни один готовый проект не был выбран: для узкой цели «поиск + фон + виджет + минимум
ресурсов» собственная реализация на PySide6 даёт контролируемый один процесс и
проверяемый контракт источника. Это подтверждается измерениями в
docs/acceptance-report.md (после сборки).

## Что осталось проверить перед публикацией продукта

- Актуальные условия Audius для распространяемого приложения (атрибуция Audius
  указана в интерфейсе; товарная публикация не входит в первую версию).
- Поведение в регионе пользователя при недоступности discovery-узлов: клиент
  использует `api.audius.co` с резервным `discoveryprovider.audius.co` и показывает
  понятную ошибку.
