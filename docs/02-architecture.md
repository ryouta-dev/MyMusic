# 02. Архитектура и данные

## 1. Выбор основы: сначала проверить, потом зафиксировать
Конечная цель задаётся docs/01, не этим стеком. Агент автономно сравнивает адаптацию существующего открытого приложения, разработку клиента с нуля и иные законные варианты. Проверить реальный поиск и фоновый звук, удобство добавления виджета, общую нагрузку всех процессов, активность проекта, лицензию и стоимость поддержки. Не выбирать основу только по обещаниям README или названию технологии. Решение и измерения записать до большой переделки интерфейса.

Кандидат с нуля: Python + PySide6 Qt Widgets, QtMultimedia QMediaPlayer/QAudioOutput для разрешённых прямых аудиопотоков; SQLite из стандартной библиотеки для локальных данных; QtNetwork для асинхронных запросов. Это предложение под проверку этапа 0, не утверждение о гарантированной нагрузке или совместимости с каждым сервисом.

Решение этапа 0 (2026-11-17): выбран вариант с нуля на Python 3.14 / PySide6 6.12 и открытый каталог Audius (без ключа и аккаунта). Реальные проверки поиска, пагинации, метаданных и direct-audio потока, а также отклонённые альтернативы записаны в [provider-validation.md](provider-validation.md). Практическая особенность: в Qt 6.12 HTTP/2 зависает на медиа-CDN Audius, поэтому запросы принудительно идут по HTTP/1.1; редиректы проверяются по allowlist доменов.

Почему: Python уже доступен, не нужен новый системный компилятор для начала; настольные элементы без Chromium; декодирование выполняет библиотека. Python не обрабатывает аудиосэмплы в цикле. Недостатки: накладные расходы интерпретатора и Qt, большой дистрибутив, особенности кодеков и упаковки. Проверить их до полноценной разработки.

Node/Electron не выбирать только потому, что Node установлен: браузерные процессы требуют отдельной оценки нагрузки, но технологию не отвергать без сравнения. C#/WPF — Windows-альтернатива; наличие .NET SDK и других сред проверить заново. Rust/C++ и прочие стеки допустимы при обоснованном выигрыше; установку отсутствующих системных сред согласовать, технический выбор не требует отдельного разрешения, если не меняет цель и согласованные границы.

Spotify Web Playback SDK не является источником прямого URL для QMediaPlayer. Его возможная интеграция требует отдельного решения с проверкой среды/DRM, правил и бюджета процессов; не добавлять WebEngine незаметно.

Если выбран вариант Python/PySide6, перед кодом проверить установленный Python, разрядность, совместимость конкретной версии PySide6 и поддержку целевой ОС. Создать .venv, зафиксировать зависимости и версии; не полагаться на skpy как среду приложения. Проверить лицензии Qt, мультимедийного бэкенда и упаковщика, включить необходимые уведомления в сборку.

## 2. Референсная схема для варианта с нуля
Если выбран готовый проект, адаптировать его архитектуру, а не переписывать ради совпадения названий классов. Обязательны единое состояние плеера для окна и виджета, корректное завершение и замер всех процессов; детали ниже — референс для PySide6.

Основное окно и виджет → ApplicationController → PlaybackController → PlaybackBackend.
ApplicationController также обращается к CatalogProvider, QueueService и Repository.

- UI рисует состояние и отправляет команды; не хранит свою копию проигрывателя.
- ApplicationController живёт до команды «Выйти», а не до закрытия последнего окна. QApplication.setQuitOnLastWindowClosed(False), системный трей, явное завершение.
- PlaybackController — единственный владелец состояния воспроизведения и очереди.
- CatalogProvider — поиск/метаданные/возможности/получение разрешённого PlaybackHandle.
- PlaybackBackend — загрузка, play/pause/seek/volume и события; QtAudioBackend первый кандидат, только для совместимого разрешённого потока.
- Repository — короткие транзакции SQLite; медленные операции вне UI-потока. Соединение БД принадлежит своему потоку.
- SettingsService и SecretStore — настройки отдельно от секретов.
- Не нужны сервер, REST API на localhost, микросервисы или отдельный постоянно работающий демон.

Будущая структура: src/mymusic/{ui,application,domain,providers,playback,storage,platform}, tests/{unit,integration}, scripts/, pyproject.toml. Не создавать пустые слои ради схемы; выделять их по рабочим сценариям.

## 3. Референсные контракты без привязки к сервису
- TrackRef: provider_id, track_id. Идентификатор провайдера обязателен, не склеивать треки разных сервисов по названию.
- Track: ref, title, artist, duration_ms?, artwork_url?, source_page_url, availability, attribution?.
- SearchPage: tracks, next_cursor?; search(query, cursor, cancellation) возвращает страницу.
- Capabilities: can_search, can_background, can_seek, can_previous, can_next, supports_full_track, requires_auth. Возможности могут зависеть от трека и подписки.
- PlaybackHandle: тип (direct_audio либо отдельный проверенный SDK), краткоживущий ресурс, expires_at?, дополнительные разрешённые параметры. Секретные URL только в памяти.
- resolve(track_ref, cancellation) → PlaybackHandle либо типизированная ошибка; повторное разрешение при истечении URL не подменяет выбранный трек.
- PlaybackSnapshot: state, track_ref?, position_ms, duration_ms?, volume, capabilities, error?.
- ProviderError: offline, unauthorized, subscription_required, rate_limited(retry_after), unavailable, forbidden, unsupported, transient. Пользовательский текст без токенов и внутренних URL.

Поиск не доказывает наличие полного трека: каталог, право на фон и реальное воспроизведение проверяются отдельно. Не вводить универсальный обход сервисов через извлечение URL.

## 4. Состояния и гонки
Состояния: idle, resolving, buffering, playing, paused, ended, error, shutting_down.
Команды сериализуются контроллером. При Next/новом треке увеличивать generation_id, отменять предыдущую загрузку и игнорировать запоздавшие события старого поколения. Один активный backend; никогда два одновременно звучащих трека.
При естественном ended — один переход к следующему элементу. При ошибке — остановка с повтором или ручным Next. Закрытие основного окна не создаёт нового backend и не сбрасывает очередь.
Повтор сетевого запроса: максимум 2 автоматические попытки при временной ошибке с задержкой и отменой; 401 — одно обновление токена, затем вход; 429 — Retry-After, без циклического опроса. После завершения приложения новые попытки запрещены.

## 5. Данные
Схема ниже относится к варианту с нуля на Python/SQLite. При адаптации готового проекта сохранять его проверенный механизм хранения и проверять эквивалентные сценарии, а не переносить таблицы механически.

Путь: %LOCALAPPDATA%/MyMusic/. База library.db, настройки settings.json с schema_version, атомарная запись через временный файл. Версии схемы и транзакционные миграции с резервной копией перед несовместимым изменением.

Таблицы первой версии:
- tracks(provider_id TEXT, track_id TEXT, title TEXT, artist TEXT, duration_ms INTEGER NULL, source_page_url TEXT, artwork_cache_key TEXT NULL, metadata_updated_at INTEGER; PRIMARY KEY(provider_id, track_id)).
- favorites(provider_id, track_id, added_at; составной PK, FK tracks).
- queue_items(entry_id TEXT PK, provider_id, track_id, ordinal INTEGER UNIQUE; FK tracks). Повтор одного трека допустим через разные entry_id.
- playback_session(id INTEGER PK CHECK(id=1), current_entry_id TEXT NULL, position_ms INTEGER, updated_at INTEGER; FK queue_items с ON DELETE SET NULL).

Включить foreign_keys, параметризованные запросы. queue_items и current_entry_id менять в одной транзакции; порядок перенумеровывать безопасно внутри транзакции. Позицию сохранять не чаще раза в 15 секунд и при паузе/смене/выходе, не каждый такт UI. Срок хранения метаданных и удаление отозванных данных зависят от правил выбранного провайдера и уточняются до его подключения.

settings.json: volume, widget_visible, widget_position, widget_topmost, theme, selected_provider, autostart(false). Положение в логических координатах с проверкой границ текущих экранов. Очередь после восстановления на паузе, недоступные записи явно помечены.

## 6. Ресурсы и безопасность
- Не крутить собственный бесконечный цикл. События Qt; таймер позиции UI максимум 2 Гц только при видимых элементах, остановлен на паузе/при скрытии.
- Асинхронная сеть; отмена запросов, тайм-аут 15 секунд, лимит параллелизма 3. Не загружать весь каталог.
- Обложки до 256 × 256 после безопасного декодирования; максимум 5 МиБ на загрузку, лимит памяти 16 МиБ и диска 50 МиБ с вытеснением. Учитывать срок кэша провайдера.
- Не запускать системное сканирование дисков, загрузку следующего аудио или обновление обложек в фоне без нужды.
- Только HTTPS-адреса доверенных провайдеров, перепроверять каждый redirect. Не исполнять URL/метаданные как команды. Блокировать loopback/private/link-local адреса для сторонних медиа; локальный OAuth callback — отдельный ограниченный механизм.
- OAuth при необходимости: системный браузер, Authorization Code + PKCE и state; проверка callback/redirect, минимальные scopes. Не просить пароль от Spotify/Google.
- Refresh token в Windows Credential Manager через проверенную библиотеку; access token в памяти. Client secret не встраивать в настольное приложение. Если API требует серверный секрет, пересмотреть провайдера/архитектуру явно.
- Логи с ротацией до 5 × 1 МиБ, без токенов, подписанных URL и поисковых запросов по умолчанию; телеметрия отсутствует.
- Выход: отменить сеть, остановить/освободить аудио, сохранить состояние, снять обработчики, закрыть БД/трей. Не оставлять дочерние процессы.
- Автозапуск только после явного включения; без прав администратора. Один экземпляр: защёлка QSharedMemory (Qt 6.12 допускает два QLocalServer с одним именем) и QLocalSocket для фиксированной команды активации.

## 7. Доставка
Для выбранного стека документировать воспроизводимую сборку и проверить её на Windows без среды разработки. Если выбран PySide6: сначала запуск из .venv, затем кандидат — PyInstaller в режиме onedir, не onefile с распаковкой при каждом старте. Версии и состав мультимедийных плагинов проверить на чистой Windows без Python. Использовать только необходимые модули; не вырезать обязательные лицензии/кодеки ради размера. Установщик, подпись и автообновления не обещаны первой версией. Сборка без подписи может показывать предупреждения Windows — сообщить это пользователю.
