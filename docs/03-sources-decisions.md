# 03. Источники, решения и неопределённости

## Реестр решений
- D01 — подтверждено: самостоятельное приложение с поиском, не медиапульт.
- D02 — подтверждено: приоритет ресурсоэффективности и фонового воспроизведения.
- D03 — предложение для варианта с нуля: Python/PySide6 Widgets без встроенного браузера, один процесс. Не обязательный стек: агент сравнит его с готовыми основами.
- D04 — допущение: плавающее окно-виджет и трей, а не системная панель Widgets Windows.
- D05 — решено 2026-11-17 в пределах свободы выбора источника: открытый каталог Audius через официальный API, без ключа, аккаунта и подписки; подтверждение и ограничения — [provider-validation.md](provider-validation.md). Каталог не равен «всем популярным песням».
- D06 — не согласовано: покупка Premium, платные API, регистрация внешнего приложения от имени пользователя, публикация приложения, установка системных сред.

Не превращать D03–D06 в подтверждённые требования. Готовые открытые плееры — кандидаты для исследования, а не утверждённый выбор. Если провайдер требует браузер/DRM, это меняет D03, а не доказывает, что его можно проиграть через QMediaPlayer.

## Готовые основы для проверки
- [Nuclear](https://github.com/nukeop/nuclear) — первый кандидат для практической проверки поиска и фонового воспроизведения; виджет и низкая нагрузка не подтверждены. Перед адаптацией проверить текущую лицензию, плагины, реальный поток и суммарную нагрузку.
- [Spotube](https://github.com/team-spotube/spotube) и [muffon](https://github.com/staniel359/muffon) — альтернативы, не выбранные реализации. Оценить их текущую сборку, источники и расход ресурсов, не считать наличие приложения доказательством права на фоновый поток.
- [Navidrome](https://github.com/navidrome/navidrome) — ориентирован на собственную коллекцию и требует отдельного клиента/виджета; без нового разрешённого интернет-источника не выполняет исходную цель.
Выбор основы, условия использования и результаты испытаний агент фиксирует в docs/provider-validation.md. Ни один проект здесь не был запущен и измерен.

## YouTube
Официальное руководство запрещает API-клиентам отделять аудиодорожку и давать фоновое воспроизведение при закрытом/свёрнутом окне. Поэтому YouTube API + скрытый аудиоплеер не является подходящим основанием для описанной первой версии.
Можно отдельно рассмотреть видимый официальный видеоплеер, но он не удовлетворяет исходной цели скрытого фонового аудио и потребует согласования изменения продукта. Не предлагать обход через cookies, yt-dlp, извлечение ссылок, блокировку рекламы или скрытый iframe.

Проверено прямым чтением официального руководства:
https://developers.google.com/youtube/terms/developer-policies-guide
Раздел «Your API service must reflect a user's standard experience on YouTube» прямо перечисляет запреты на отделение аудио и background play.
Полные правила: https://developers.google.com/youtube/terms/developer-policies

## Spotify
Официальная страница Web Playback SDK описывает клиентскую JavaScript-библиотеку для браузера и требует Spotify Premium (исключая mobile-only подписки). В ней также указано, что коммерческое использование требует предварительного письменного согласия Spotify.
https://developer.spotify.com/documentation/web-playback-sdk

Из этого НЕ следует:
- что Web API отдаёт произвольные прямые аудиоссылки;
- что SDK гарантированно работает в PySide6/WebEngine или другом настольном контейнере;
- что у пользователя есть Premium, аккаунт разработчика или нужный доступ API;
- что встроенный браузер уложится в бюджет ресурсов;
- что обычная удалённая команда Spotify Connect делает MyMusic самостоятельным проигрывателем.

До выбора проверить текущие ограничения режима разработки/квот/регионов, разрешённую среду SDK, DRM, авторизацию, паузу и Next при скрытом основном окне. Авторизация через PKCE — кандидат, точные redirect/scopes проверять по актуальным правилам:
https://developer.spotify.com/documentation/web-api/tutorials/code-pkce-flow

## Другой интернет-каталог
Кандидаты для исследования — каталоги независимой/открыто лицензированной музыки, например Jamendo. Это не выбранный источник, не подтверждение бесплатности и не гарантия популярных песен. Страница Jamendo API при текущей проверке не загрузилась; условия не подтверждены.
Проверить: поиск реальных треков, доступ к полному аудио, право на фон, доступ для личного настольного приложения, атрибуция, срок кэша, лимиты, требование ключа/секрета, запреты на распространение, доступ из региона пользователя. Не заменять каталог набором тестовых MP3 или радио без согласования.

## Проверка источника — обязательный допуск
В будущий docs/provider-validation.md записать для каждого кандидата:
1. Ссылки на актуальные условия и конкретные разрешения/ограничения, дату проверки.
2. Реальный сценарий: поиск → полный трек → пауза → следующий → 10 минут со скрытым основным окном.
3. Нужные аккаунты, подписку, ключи и сервер; секреты в отчёт не включать.
4. ОС, окружение, backend, кодеки, набор доступных возможностей.
5. CPU, private bytes всех процессов, GPU, сеть; ограничения и ошибки.
6. Вывод: подходит / не подходит / не проверено, с причиной и подтверждениями.

Если ни один проверенный источник не подходит, передать пользователю развилку: меньший каталог с разрешённым аудио либо Spotify с подтверждёнными условиями и большим расходом ресурсов. Не менять продукт на локальные файлы/пульт без согласия.

## Основания выбора инструментов
Qt for Python и QMediaPlayer, ссылки для следующего агента:
https://doc.qt.io/qtforpython-6/gettingstarted.html
https://doc.qt.io/qtforpython-6/PySide6/QtMultimedia/QMediaPlayer.html
Веб-страницы Qt доступны, но выдача инструмента была обрезана длинным меню; конкретные версии, кодеки и API не считаются проверенными испытанием. Проверить по документации установленной версии и прототипу.
Альтернатива WPF (только Windows): https://learn.microsoft.com/en-us/dotnet/desktop/wpf/overview/

## Сводка границ исследования
Документы созданы после чтения официальных материалов, но без входа в сервисы, регистрации приложений, покупки подписок и реального воспроизведения. Две страницы Spotify policy/Web API первоначально не загрузились по тайм-ауту; условия по ним не выдумывались. Сведения о SDK подтверждены отдельной доступной официальной страницей. При реализации перепроверить правила: они меняются.
